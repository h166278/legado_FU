# 导演层：场景上下文

为每个 `character` 和 `thought` 整理当前台词所在的局部场景。先按 `sceneId` 阅读完整连续场景，再围绕目标台词保留真正影响演绎的信息：

1. 人物此前的处境、关系或持续状态。
2. 触发当前发言的动作、对话或事件。
3. 发言之后紧邻的身体反应、动作承接或状态变化。

按事情发生的顺序写成 1～3 条自然短句。优先保留犹豫、停顿、发抖、红脸、哽咽、哭泣、强忍情绪等可影响声音的事实。短对白仍要继承完整场景中持续有效的处境、关系和说话目的，不能因为台词短或属于普通问答而丢掉上下文。

`performanceContext` 描述人物为什么在此刻这样说，让 TTS 理解基本演法。至少包含处境／持续状态／关系立场／即时触发／交流目的中的两项；不能只把目标台词改写成“某人询问某事”“某人说会处理某事”之类事件摘要。保持原文事实、人物视角和不确定性，不写音色参数，不复制目标台词，不用单个情绪标签代替场景。

每条不超过 80 个字符，总长度不超过 220 个字符。启用导演层时，`character` 和 `thought` 必须返回至少一条有效场景；`narrator` 和 `other` 返回空数组。

普通询问也应说明关系和目的，例如“对方仍因困境而局促；说话人想确认信息并继续提供帮助”，而不是只写“说话人询问联系方式”。
